## 1. 背景与现状评估

### 1.1 需求复述

用户要求：以「资深前端工程师 + 高级 UI 设计师」标准重构前端界面，形成符合「途笺」品牌气质的美学体系，并评估需要拓展的功能。约束：不改变后端 API 语义（可增加只读计数字段）、不引入重型依赖、移动端优先。

### 1.2 现状问题清单（实测代码得出）

| # | 问题 | 证据 | 影响 |
|---|---|---|---|
| 1 | 桌面端布局被脚手架样式破坏 | `assets/main.css`：≥1024px 时 `#app{display:grid;grid-template-columns:1fr 1fr}` | 桌面端页面只占半屏，最大隐藏 Bug |
| 2 | 脚手架残留 | `stores/counter.ts`、`App.vue` 中 header/nav 死样式、`assets/base.css` 整套 Vue 主题变量与暗色模式 | 认知负担、样式漂移 |
| 3 | 编辑能力全部缺失 | 后端有 `PATCH /trips/{id}`、`/days/{id}`、`/places/{id}`；`api/trips.ts`、`days.ts`、`places.ts` 均无 update 函数 | 用户无法改错字/改日期/调整地点 |
| 4 | 地点删除无二次确认 | `TripDetailView.vue:143` 直接 `deletePlace` | 误删风险（天和行程都有确认，唯独地点没有） |
| 5 | 视觉与品牌无关 | 灰白背景 + Element Plus 默认蓝，emoji 当图标（📍🗓🕐） | 与「途笺」气质无关，PC/移动一致性差 |
| 6 | 无状态/倒计时/天数展示 | `status` 字段存在但前端未展示；卡片无天数、地点数 | 信息密度低，无法一眼看到"何时出发" |
| 7 | 交互未移动端适配 | 表单用居中 dialog（手机上拇指够不到）；无 FAB；无安全区处理 | 移动端体验差 |
| 8 | 无排序能力 | `sort_order` 字段与更新接口均存在，前端未使用 | 行程顺序无法调整 |
| 9 | SEO/元信息缺失 | `index.html`：`lang=""`、`<title>Vite App</title>` | 标签页/分享卡片显示错误 |
| 10 | 删除/空态/加载体验粗糙 | 加载只有 `v-loading` 遮罩；空态是 el-empty 默认插图 | 缺乏质感 |

### 1.3 复杂度分类

- 算法复杂度：无（无算法问题）。
- 工程复杂度：**中高**。难点不在单个页面，而在：① 建立一套与 Element Plus 共存的**设计令牌体系**并系统性覆盖默认皮肤；② 抽象出可复用的组件层，避免每页 hack；③ 在无新依赖前提下解决移动端表单/交互（dialog ↔ 抽屉双形态）。
- 若按页面零散改样式（症状级），将出现：色值散落、组件重复、EP 覆盖互相打架，后续每加一个页面成本递增。因此选择"令牌 + 组件 + 统一覆盖"的系统化方案。

## 2. 设计概念与美学方向

### 2.1 核心概念：「纸上旅途 · 手账质感」

「笺」= 精美的纸、信笺、便签。设计隐喻取**旅行手账**：宣纸底色、墨色文字、朱砂印章、票根卡片、虚线时间轴。

美学原则：
1. **纸的温度，现代的秩序**——不是做旧的伪古董：大量留白、清晰层级、克制的点缀色，避免"土味复古"。
2. **一印点睛**——朱砂红只用于关键动作用与印章标记，全屏占比 <5%。
3. **信息优先**——装饰永远不牺牲可读性；楷体仅用于品牌与日期点缀，关键信息用无衬线 + 表格数字。
4. **纸感来自细节**：噪点纸纹（SVG 内联，零资源）、暖色阴影、微旋转、虚线分隔。

反面清单（明确不做）：渐变紫蓝 SaaS 风、玻璃拟态、emoji 图标、大面积深色、圆角过度的"气球感"。

### 2.2 视觉令牌（唯一来源：`src/styles/tokens.css`）

```css
/* 纸张与墨色 */
--wy-paper-bg:    #F7F3EC;   --wy-paper-card:   #FFFDF8;   --wy-paper-sunken: #F1EBE0;
--wy-ink-1:       #2A2622;   --wy-ink-2:        #574F46;   --wy-ink-3:        #8A8177;
--wy-line:        #E7DFD2;   --wy-line-strong:  #D8CDBB;
/* 点缀色（朱砂 / 黛青 / 苔绿 / 赭金） */
--wy-cinnabar:    #B5432E;   --wy-cinnabar-weak:#F3E2DC;
--wy-indigo:      #3F5A66;   --wy-indigo-weak:  #E3EAEC;
--wy-moss:        #5F7259;   --wy-moss-weak:    #E7EDE4;
--wy-gold:        #C89B3C;   --wy-gold-weak:    #F5EBD7;
/* 字体：标题/点缀用楷体栈（系统自带，零下载）；正文无衬线；数字用表格数字 */
--wy-font-display: "LXGW WenKai", "Kaiti SC", "STKaiti", KaiTi, "Noto Serif SC", serif;

配套：`body::before` 固定层叠加 SVG feTurbulence 噪点（opacity 0.035，`pointer-events:none`）；`prefers-reduced-motion` 时关闭动效。

### 2.3 Element Plus 共存策略

保留 Element Plus（组件质量、无障碍基础好），通过**单一覆盖文件 `src/styles/element.css`** 重设 CSS 变量与关键组件皮肤：

- `--el-color-primary` 及 9 档色阶 → 朱砂系；圆角、边框、输入底色 → 纸面；
- 重皮肤清单：Button / Input / Select / DatePicker / Dialog / Drawer / Message / MessageBox / Tag / Skeleton；
- 原则：能用官方 CSS 变量就不写选择器；选择器覆盖集中在 element.css，**页面组件内禁止覆盖 EP 内部类**（防复发规则）。

## 3. 页面设计

### 3.1 登录 / 注册（同构双栏）

```
桌面 ≥900px                                   移动 <900px
┌───────────────┬──────────────┐            ┌──────────────┐
│               │              │            │     〈印〉    │
│   〈途笺印〉   │   欢迎回来     │            │   途笺       │
│  "把旅途，     │  ┌─────────┐ │            │  把旅途      │
│   写成一纸手账" │  │ 邮箱     │ │            │  ┌────────┐ │
│               │  │ 密码     │ │            │  │ 邮箱    │ │
│  虚线路线装饰  │  └─────────┘ │            │  │ 密码    │ │
│               │  [ 登 录 ]    │            │  └────────┘ │
│               │  去注册 →     │            │  [ 登 录 ]   │
└───────────────┴──────────────┘            └──────────────┘

要点：左栏纸底 + 朱砂印（楷体"途笺"+ 白文印效果）+ 一条虚线路线 SVG；表单**标签在输入框上方**（不再仅靠 placeholder）；错误内联显示（保留 toast）；输入聚焦 2px 朱砂轮廓。

### 3.2 行程列表

```
顶栏：〈印〉途笺 WayNote                       [头像▾ 退出]
──────────────────────────────────────────────
我的行程                        共 3 段 · 2 段待出发   [+ 新建]
[全部] [待出发] [旅途中] [已结束]                ← 筛选 chips
┌─ 票根卡片 ────────────┐ ┌────────────────────┐
│ 京都三日游        〔待出发〕│ │ 北海道滑雪           〔已结束〕│
│ 📍 京都               │ │ 📍 北海道                    │
│ 10月1日 – 10月3日 · 3天│ │ 2月2日 – 2月8日 · 7天 4晚      │
│ 还有 12 天 · Day3 · 6地点│ │ 共 21 个地点                  │
└───────────────────────┘ └────────────────────────────┘
```

- **票根卡**：纸面卡片 + 顶部目的地色条（由目的地名哈希到 6 色莫兰迪色板，同目的地恒定）+ 右上角**印章状态**（待出发=赭金描边 / 旅途中=苔绿实底 / 已结束=淡墨"已归档"）+ 底部虚线"撕票线"分隔统计行。
- 状态与倒计时**由日期推导**（`planning/ongoing/finished/undated`），不依赖手工 status；无日期行程归入"待出发"并在卡上标"未定日期"。
- 右上 `···` 菜单：编辑 / 删除；删除走统一样式确认框。移动端此按钮常显，桌面 hover 显示。
- 空态：内联 SVG 线稿（行李箱 + 虚线路线）+ 楷体"还没有行程，去写下第一段旅途吧"。
- 加载：骨架卡（EP Skeleton 换纸色皮肤）。
- 移动端新增：右下 FAB（朱砂圆钮）承载"新建行程"。

### 3.3 行程详情

```
[← 返回]                         [编辑行程] [···]
╔═ 头部 ══════════════════════════════════════╗
   〔旅途中〕 京都三日游                       ← 楷体 26-30px
   📍 京都 · 10月1日 – 10月3日 · 3天 · 6个地点 · 还剩2天
╚═════════════════════════════════════════════╝
  ┆
  ●─ Day 1  10月1日 周四 · 抵达京都            [＋地点] [✎] [🗑]
  ┆   ┌ 🕐 14:00–16:00  清水寺  〔寺庙〕        ↑ ↓ ✎ 🗑
  ┆   │   📌 東山区清水1丁目            [地图↗]
  ┆   └ 备注：记得带御守
  ●─ Day 2 …
  ┆
  ┄┄┄ 待定地点（虚线便签容器）┄┄┄
      奈良公园   [安排到某天 ▾]
```

- 时间轴：左侧虚线导轨 + 圆点节点（朱砂描边）；天卡片用 `Day N` 方形徽章 + 日期 + 星期 + 自定标题（楷体）。
- 地点行：时间胶囊（table 数字）、名称、分类小印章、地址、备注引用块；行内操作：上移/下移（`sort_order` 交换）、编辑、删除（**补确认**）、有坐标时显示"地图↗"（腾讯 URI `apis.map.qq.com/uri/v1/marker`，无需 key），无坐标时提供"复制地址"。
- 待定地点（`day_id=null`）：虚线容器 + "安排到某天"下拉（调用既有 PATCH 接口移动）。
- 空态：无天时若行程有起止日期 → CTA「按行程日期生成 3 天」（顺序调用 createDay 避免 day_index 竞态）；无日期则引导"添加一天"。
- 表单统一走 `FormSheet`：桌面 `el-dialog`，移动端底部 `el-drawer`（圆角上沿、安全区 padding）。

### 3.4 全局

- 路由切换 150ms 淡入上移动画（reduced-motion 关闭）；`document.title` 随路由（`途笺 · 行程`）。
- `index.html`：`lang="zh-CN"`、title「途笺 WayNote」、`theme-color=#F7F3EC`、description、SVG favicon（朱砂印「途」字）。
- 图标：自研 `AppIcon.vue`（约 20 个内联 SVG，1.6px 描边，currentColor），**不引入图标依赖**，彻底替换 emoji。

## 5. 范围选项

- **A 纯视觉重构**：仅设计系统 + 4 页面视觉与响应式，不接新接口。风险最低，但"改错字要删了重建"的痛点仍在。

- **C B + 部分 P1**：再加本地搜索、PWA manifest、a11y 收尾。

## 7. 风险、边界与反例

| 风险/边界 | 说明 | 对策 |
|---|---|---|
| EP 皮肤覆盖泄漏或打架 | 全局覆盖与 scoped 样式冲突 | 覆盖集中在 element.css；页面禁止改 EP 内部类；验收时逐组件回归 |
| dialog→抽屉双形态复杂度 | 每个表单两套交互易散落 | 统一 `FormSheet` 封装，页面只声明内容 |
| 长文本溢出 | 超长标题/地址/备注 | line-clamp + title 提示；备注限高折叠 |
| 日期边界 | 跨月/跨年范围、无日期行程、时区 | 统一 `utils/trip.ts` 格式化；仍按 `slice(0,10)` 取本地日期，不做时区换算 |
| `#app` 栅格 Bug 修复 | 会改变桌面现有布局 | 属目标修复，逐页目视验收 |
| 浏览器工具可能无法访问 localhost | 视觉验收通道不确定 | 若不可用：type-check/build/lint + 手动验收清单 + 本地 dev 自查 |
| 楷体可用性 | 非中文系统无楷体 | 仅作装饰；回退 serif；关键信息用无衬线 |
| 计数字段影响既有测试 | TripOut 语义不变，新类型仅列表使用 | 保持 `get_trip` 原响应；新增用例覆盖列表计数 |

## 8. 防复发机制

1. **颜色单一来源**：`scripts/check-tokens.mjs` 扫描 `src/`，禁止 tokens.css 以外出现十六进制色值（白名单：element.css 注释行），挂到 `npm run lint` 前置；防止后续随手写色值导致体系腐化。
2. **脚手架残留清零**：删除 counter.ts / 旧 css / App.vue 死样式，避免"以错为范"。
3. **ADR 记录设计令牌与 EP 共存规则**，作为后续新增页面的唯一依据。
4. 后端计数逻辑进 pytest，防止未来重构丢字段。

## 10. 被否决的替代方案

| 方案 | 否决理由 |
|---|---|
| 引入 Tailwind / 重写组件库 | 与现有 EP 栈冲突，迁移成本远超收益 |
| 引入 sortablejs 做拖拽 | 新增依赖 + 触屏边界多；上移/下移按钮满足需求且 a11y 友好，拖拽列 backlog |
| 下载 LXGW 文楷 webfont | 完整 CJK 字体数 MB，首屏代价大；系统楷体栈零成本达到 80% 效果 |
| 整站换深色/摄影风 | 与"笺"的纸感矛盾；深色模式列后续迭代 |
| 每页单独调样式（症状级） | 色值/组件散落，后续页面成本递增，无法收敛 |
| 前端 N+1 请求卡片计数 | 行程列表会发 2N 请求；后端标量子查询成本更低 |

## 11. 待确认问题

1. 美学方向：确认「纸感手账（宣纸+朱砂+黛青）」为主方向？或改用替代方案「现代清简（冷白+黛青）」？
