# ADR-20261010-Waynote-auth-rate-limit

**状态**：已确认并实现（用户点名"只做第 4 项：应用层"）
**任务**：密码登录频控 + 生产关闭 API 文档

---

## 1. 背景与威胁（实测证据，非假设）

| 证据 | 数值 |
|---|---|
| 服务器近 7 天 SSH 密码爆破 | **6373 次**（root 3631 · ubuntu 822 · meikenai 434 …） |
| 爆破来源 Top1 | 51.89.42.211（2233 次） |
| `/auth/login` 频控 | **无**（当时可无限次试密码） |
| bcrypt cost=12 | 单连接约 4 次/秒；分布式/字典攻击不受限 |
| FastAPI 默认文档 | `/docs` `/redoc` `/openapi.json` 线上实测 **200**（未鉴权的接口地图） |

> 结论：机器已被扫描器纳入名单；应用层当时唯一的上限是 bcrypt 的算力成本。

## 2. 根因

认证层只有"凭据校验"，**没有"尝试成本"**：失败不记账 ⇒ 攻击者边际成本为 0。
对照组：邮箱验证码通道有"单码 5 次 + 四层频控"（见 ADR-20261009），同类防护在密码通道缺失。

## 3. 设计

### 3.1 密码登录失败频控

- **只对失败记账**：成功登录不消耗额度（正常用户完全无感；也避免"登录多了被锁"）
- **两个维度都要过**：
  - 每 **IP**：10 次失败 / 5 分钟 —— 挡单点暴力
  - 每**邮箱**：5 次失败 / 5 分钟 —— 挡分布式针对单账号
- 判定顺序：**先 peek（只读）再校验** —— 已超限的请求直接 429，不白做 bcrypt
- 超限响应：**429** + 剩余秒数 + 可行动指引（"也可以用「验证码登录」"）；审计 `auth.login.rate_limited`
- IP 取值走既有信任边界（`core/net.py`）：仅可信代理的 XFF 被采信 ⇒ **伪造 XFF 不能换桶**
- **不做全局上限**：攻击时会把所有正常用户一起拒之门外（自伤），而"每邮箱"已保证单账号安全

### 3.2 生产关闭 API 文档

- 新配置 `DOCS_ENABLED`，**默认 false**（secure by default）
- 关闭时 `docs_url/redoc_url/openapi_url` 全部为 `None`（**不注册路由**，而不是靠鉴权遮挡）
- 本地开发在 `backend/.env` 里设 `DOCS_ENABLED=true`（README 里的 http://127.0.0.1:8000/docs 照旧可用）

## 4. 泛化边界与反例

| 维度 | 说明 |
|---|---|
| 适用 | 单进程内存限流（与 `client_logs` / `email_code` 同一边界，见 ADR-20260929） |
| 反例 1 | 攻击者用 5 次失败把某邮箱锁 5 分钟（DoS）→ 缓解：**验证码登录通道不受影响**，用户可改道进入；窗口 5 分钟自动过期 |
| 反例 2 | 共享出口 IP（公司/学校 NAT）里有人触发 IP 维度 → 5 分钟后自动恢复；不牵连其它邮箱（邮箱维度独立） |
| 反例 3 | 攻击者持有合法账号 → 成功登录不记账，不会因"攻击"被封；其攻击能力仍被 IP/邮箱两维度限制 |
| 不适用 | 多进程/多副本部署（需 Redis 或表级计数）——已知遗留 |

## 5. 测试（`backend/tests/test_login_rate_limit.py`）

| ID | 场景 | 期望 |
|---|---|---|
| T1 | 同邮箱 5 次失败后（含正确密码） | 429 + 剩余秒数 |
| T2 | 同 IP 跨 10 个邮箱失败 | 第 11 次 429 |
| T3 | 4 次失败 + 1 次成功 + 1 次失败 | 全部按预期（成功不记账，第 5 次失败仍放行，再往后 429） |
| T4 | 不可信直连伪造 XFF 换邮箱 | 仍按同一 IP 分桶 → 429 |
| T5 | 文档开关接线 | `_docs_kwargs(False)` 三者 None；`(True)` 空 dict |
| T6 | 回归：正常密码登录 | 200 + token |

## 6. 与云侧加固的分工（用户决定）

- 本次**不做**（用户暂缓，已记录）：SSH 关密码登录、安全组收窄 22、启用腾讯云主机安全（免费版）
- 分层模型：网络层/主机层可由云侧承担（安全组 + 主机安全），但**应用层云看不见**（安全组只认端口/IP）——本 ADR 补的正是这一层
- 遗留：应用层限流仍是单进程内存态；8090 仍为明文 http（等备案后上 80/443 + certbot）
